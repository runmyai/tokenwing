# Settings

Each mechanism is a flag. Most are off by default, so plain TokenWing behaves like llama.cpp; the autotuner sets the values for your machine and model. `--help` prints the same text, and the rest of llama.cpp's settings.

## Model and context

| Flag | What it does |
|---|---|
| `-c, --ctx-size N` | size of the prompt context (default: 0, 0 = loaded from model) (env: LLAMA_ARG_CTX_SIZE) |
| `-n, --predict, --n-predict N` | number of tokens to predict (default: -1, -1 = infinity) (env: LLAMA_ARG_N_PREDICT) |
| `--swa-full` | use full-size SWA cache (default: false) [(more info)](https://github.com/ggml-org/llama.cpp/pull/13194#issuecomment-2868343055) (env: LLAMA_ARG_SWA_FULL) |
| `-fa, --flash-attn [on\|off\|auto]` | set Flash Attention use ('on', 'off', or 'auto', default: 'auto') (env: LLAMA_ARG_FLASH_ATTN) |
| `-ctk, --cache-type-k TYPE` | KV cache data type for K allowed values: f32, f16, bf16, q8_0, q4_0, q4_1, iq4_nl, q5_0, q5_1 (default: f16) (env: LLAMA_ARG_CACHE_TYPE_K) |
| `-ctv, --cache-type-v TYPE` | KV cache data type for V allowed values: f32, f16, bf16, q8_0, q4_0, q4_1, iq4_nl, q5_0, q5_1 (default: f16) (env: LLAMA_ARG_CACHE_TYPE_V) |
| `-np, --parallel N` | number of server slots (default: -1, -1 = auto) (env: LLAMA_ARG_N_PARALLEL) |
| `-m, --model FNAME` | model path to load (env: LLAMA_ARG_MODEL) |
| `--quant-plugin PATH` | shared library (.so / .dll) registering external GGML quantization types GGML_TYPE_EXT0..EXT5 (default: none) (env: LLAMA_ARG_QUANT_PLUGIN) |
| `--host HOST` | IP addresses to listen on, comma-separated, or UNIX socket paths ending in .sock; with multiple TCP addresses, :: binds IPv6 only; overlapping addresses result in undefined behavior (default: 127.0.0.1) (env: LLAMA_ARG_HOST) |
| `--port PORT` | port to listen (default: 8080) (env: LLAMA_ARG_PORT) |
| `--api-key KEY` | API key to use for authentication, multiple keys can be provided as a comma-separated list (default: none) (env: LLAMA_API_KEY) |
| `--api-key-file FNAME` | path to file containing API keys, one per line; lines starting with a hash are treated as comments (default: none) (env: LLAMA_ARG_API_KEY_FILE) |

## The experts file and pools

| Flag | What it does |
|---|---|
| `--moe-stream PATH` | stream the routed MoE experts from the repacked sidecar described by PATH (the "<sidecar>.json" of tokenwing-tools/experts/expert_repack.py) into per-layer slot pools in RAM instead of reading them from the model file. The word `model` streams from the model file itself, which then has to be a TokenWing model file (tokenwing-tools/experts/make_model_file.py: the same GGUF with every tensor on a 4096-byte boundary, checksums of sample experts, and optional data appended after the last tensor), so one file is all there is; any other file is refused with one line. A read of an expert is then one request per projection (gate, up, down), each at its own place in the file |
| `--moe-stream-slots N` | expert slots per MoE layer for --moe-stream, must be >= 3*moe_expert_used and <= the number of experts a layer has (default: as many as the RAM budget pays for, see --moe-stream-ram) |
| `--moe-stream-plan-only` | print the plan of --moe-stream (slots, pool RAM, streamed layers) and stop, loading nothing |

## RAM

| Flag | What it does |
|---|---|
| `--moe-stream-hugepages 0\|1` | allocate the expert pools 2 MiB-aligned and madvise(MADV_HUGEPAGE) them, so that a 3.13 MB expert slice spans 2 page-table entries instead of about 765 4 KiB ones (default: 0 = off, since no MoE measurement of THP exists) |
| `--moe-stream-pin 0\|1` | register the expert pools with the CUDA driver (cudaHostRegister) so that RAM->VRAM copies run at full speed and the pool cannot be swapped (default: 0 = off; needs a CUDA context, and the registration of a 20 GiB pool takes seconds) |
| `--moe-stream-nonpool-measured 0\|1` | 1 = the memory held back outside the expert pools comes from this run's own needs: the KV cache, the host compute buffers and the rest of the process are measured in the run and kept in a record next to the sidecar (<sidecar>.nonpool.txt, or <model>.gguf.nonpool.txt next to the model file with --moe-stream model; one line per set of settings); the next start with the same settings sizes the pools from it. Without a record: the fixed reserve. A start that needs more than planned gives back slots, one line (default: 0) |
| `--moe-stream-nonpool-growth SIZE` | with --moe-stream-nonpool-measured 1: bytes held back on top of the record (default: 128MiB) |
| `--moe-stream-ram SIZE` | RAM budget for the --moe-stream expert pools, e.g. 20GiB; the slots per MoE layer follow from it. It is a cap: the pools never take more than what the machine can spare (see --moe-stream-ram-free), and --moe-stream-slots wins over both |
| `--moe-stream-ram-free SIZE` | RAM to keep free for everything else (the RAM headroom), so the expert pools are sized from what the machine can spare: MemAvailable - this - the weights that stay in RAM. The same number in both modes: without --moe-stream-elastic the pools are sized once at start to leave it free (no give-back, no take-back); with --moe-stream-elastic 1 RAM is filled up to it, given back at once below it and taken back slowly above it. A negative value keeps no margin (default: --moe-stream-ram-margin when given, else 1280MiB Linux [or kernel zone high watermarks + 768MiB], 1536MiB Windows/macOS, 2GiB when no swap/pagefile is configured) |
| `--moe-stream-other-rest SIZE` | llama-server with --moe-stream: the memory the rest of the process uses next to the pools, the weights in RAM and the server's snapshots (the KV cache, the compute buffers, the CUDA host allocations), as measured on one machine and model; what the 1.51GiB non-pool reserve has left above it holds the server's snapshots and its --cache-disk restore buffer, and only what does not fit costs slots (default: 0 = 1093MiB, measured with Ling-3.0-flash at -c 16384 -np 1) |

## Prediction

| Flag | What it does |
|---|---|
| `--moe-stream-pred-shared 0\|1` | predict the next layer's experts from the residual plus the *shared* expert's output of this layer, i.e. run the next router on what the residual will be minus the routed part (Colibri's idea; on a model with hyper-connection streams, e.g. qwen4exp, the guess input is the wide residual plus this layer's gated shared expert, mixed with the target layer's FFN weights; default 0 = off because it makes the prediction wait for the shared expert, which is device work the layer already issued) |
| `--moe-stream-prefetch 0\|1` | prefetch the experts that the next layer's router predicts (default: 1) |
| `--moe-stream-prefetch-m M` | experts predicted per token for the next MoE layer (default: 0 = the model's experts per token, e.g. 8 on Ling, 6 on Flint) |
| `--moe-stream-prefetch-lead N` | MoE layers of lead for the expert prefetcher: 1 predicts the next layer only (default), 2 also guesses the layer after it now and corrects that guess at the next layer |
| `--moe-stream-prefetch-m2 M` | experts the correction of a two-layer-lead guess covers (default: 0, the same as --moe-stream-prefetch-m; measured 0.855 recall at 16/12 against 0.760 at 8/8) |
| `--moe-stream-early-order BOOL` | make this layer's expert ids depend on the early-guess op, so the guess is issued before the layer's own expert work instead of whenever the scheduler finds it ready (default: false; the dependency is exact - a zero added to the ids - so the output does not change) |
| `--moe-stream-needed-early 0\|1` | with --moe-stream-plan 1, a decode word's 1-ahead guess is handed to a helper thread that makes its waiting-list entries (skipped when the guessed layer has already started); the first part of putting the needed reads first and the shared expert and the guess on the GPU during the CPU experts (default: 0). Needs --moe-stream-plan 1 |
| `--moe-stream-guess-top K` | with --moe-stream-plan 1, a decode word's 1-ahead guess puts its first K ranks on the waiting list: ranks 1..k (the model's pick count) first, then k+1..K, read in the drive's spare time like every list entry; K must be >= k and <= 32; prompt ubatches keep --moe-stream-prefetch-m (default: 0 = off, the guess width is --moe-stream-prefetch-m). Needs --moe-stream-plan 1 |
| `--moe-stream-lookahead N` | each streamed layer also guesses the streamed layers 2..N ahead (the recorder's lead-d guess: the target's router on this layer's guess input); the waiting list keeps votes and the latest rank per entry and is re-sorted once per layer (live before dropped, top k before extra ranks, nearest target, more votes, better rank) (default: 2, recommended; 1 = the 1-ahead guess only, max 8). N > 1 needs --moe-stream-plan 1 and --moe-stream-drop-stale 1: without them the default falls back to 1 by itself and a value you give is switched off with one line; only decode calls of one token use it (other call shapes keep the 1-ahead guess); refused at load on an architecture whose graph does not build the far guesses |
| `--moe-stream-guess-pace B` | with --moe-stream-lookahead N > 1, a far guess (2 or more layers ahead) adds at most B new waiting-list entries for its target; its other names still vote (default: 1; unused at N = 1) |
| `--moe-stream-guess-combined 0\|1` | with --moe-stream-lookahead N > 1, a layer's N guesses in one step - one norm, one multiply by the N targets' gains, the N router products in one op (each row by the same matmul code as a separate guess), one gating, one top-k with a bias per row - bit-identical to the separate ops (default: 0 = the separate ops) |
| `--moe-stream-wordstart D` | in a decode word of one token, the last D layers before the first streamed layer (VRAM MoE layers, or dense layers) each guess the streamed layers 1..N ahead of them (N = --moe-stream-lookahead), as a streamed layer guesses; one CPU op after the last of them adds the guesses to the waiting list in the order the layers ran. D above the number of layers before the first streamed one is clamped. Needs --moe-stream-plan 1 and --moe-stream-drop-stale 1 (default: 0 = off) |
| `--moe-stream-chance-model FILE` | probability table (JSON) for the 1-ahead guess: read every candidate not in RAM whose probability is at least --moe-stream-read-threshold, best first, instead of the top --moe-stream-prefetch-m (default: off) |
| `--moe-stream-read-threshold P` | with --moe-stream-chance-model: the probability a 1-ahead candidate needs to be read (default: 0.3) |
| `--moe-stream-correction FNAME` | the trained correction file of the router-trick guess (tokenwing-tools/correction/make_correction.py). For each (layer, lead) pair in the file the guess is made with W' = W_X*g_X + Bt (or W' = W_X + Bt on hyper-connection models without ffn_norm) instead of W_X (same product, same cost); the matrices are allocated on the routers' own devices at model load, so a later --moe-stream-vram-free sees them as used VRAM. Needs --moe-stream-pred-shared 1. The model's router tensors may be F32, BF16 or F16 (BF16 and F16 are converted to F32 at load); the selection bias is hashed into the file's model check whenever the model has it and is required only for `bailingmoe3`. A damaged file, another model or quant, or a setting it does not fit = the plain guess and one line saying why, never an abort. The word `model` takes the correction appended to a TokenWing model file (make_model_file.py --correction); a model file without one gives the plain guess and one line (default: unset = the plain guess) |
| `--moe-stream-guess-skip-full 0\|1` | 1 = with --moe-stream: a reply word's combined guess skips the target layers that hold every expert in RAM (all READY; checked at every call's start, so a layer that loses an expert - a prompt's give-back, an eviction - is guessed again from the next word). The same text; the guess's own CPU work saved where layers are full. CPU-only machines; a GPU machine's guess is unchanged (its skip is --moe-stream-guess-skip-full-gpu) (default: 0) |
| `--moe-stream-guess-skip-full-gpu 0\|1` | 1 = with --moe-stream-guess-skip-full 1 on a GPU machine: the GPU's combined guess (its router rows) and its top-k skip the target layers that hold every expert in RAM; the engine copies the 'full' bytes to the GPU at each call's start, the kernels read them there (a CUDA GPU; elsewhere nothing changes). The same text (default: 0) |

## SSD reads

| Flag | What it does |
|---|---|
| `--moe-stream-io-threads N` | number of threads that read the expert sidecar for --moe-stream (default: 8) |
| `--moe-stream-overlap 0\|1` | compute a layer's experts whose bytes have already landed while the missing ones are still being read: remap() returns after issuing the reads and ggml's mul_mat_id waits per slot, in a second pass over the experts, so the resident work hides under the read. Lossless - the same columns are computed by the same matmuls - but it moves a wait into the CPU backend, so it is off by default until it is measured |
| `--moe-stream-chunk KiB` | split every demand read of an expert into chunks of this many bytes, so that the I/O threads serve one read in parallel. With --moe-stream model a chunk is a piece of one projection (gate, up or down) and never crosses into the next, and 0 still means one request per projection (default: 0 = one read per expert) |
| `--moe-stream-chunk-prefetch KiB` | the same for a prefetch read, which is not on the critical path (default: 0 = one read per expert) |
| `--moe-stream-demand-last BOOL` | let a queued prefetched read overtake a demand read (default: false, i.e. a demand read, which the compute is waiting for, always overtakes a prefetch) |
| `--moe-stream-prefetch-inflight N` | cap the guessed reads in flight at once (default: 0, no cap). Measured on one drive that a needed read takes 0.76 ms on an idle drive and ~4.7 ms with eight reads queued, so a wide early guess can make the stall worse than no guess; a needed read never waits for this cap |
| `--moe-stream-io-wake read\|chunk` | how many I/O threads a queued read wakes: one per read (default) or one per chunk, so the chunks of a guess run in parallel |
| `--moe-stream-plan 0\|1` | 1 = a decode word's 1-ahead guess puts its experts on a waiting list, and an I/O thread takes a RAM slot for one (and queues its read) only when it has nothing else to read (late binding); the list is empty at every word's end (default: 0 = the plain path, the guess's reads are queued at once). Not with --moe-stream-prefetch-lead > 1, -prefetch-inflight, -early-order, -demand-last, -oracle or -chance-model / -read-threshold |
| `--moe-stream-drop-stale 0\|1` | with --moe-stream-plan 1, when a layer starts, its waiting-list entries it did not pick are removed (never read, never take a slot), and its started guess reads it did not pick lose their pieces not yet read (the slot is freed); pieces already being read finish (default: 0 = they are read anyway). Needs --moe-stream-plan 1 |
| `--moe-stream-behind-backlog B` | with --moe-stream-plan 1 and --moe-stream-behind-rank, the drive counts as behind while B or more reads (needed reads and started guess reads, whole reads, waiting or in service) are not finished; while behind, a reader binds only waiting-list entries ranked R or better (the others wait on the list) (default: 0 = off). Needs --moe-stream-plan 1 |
| `--moe-stream-behind-rank R` | with --moe-stream-behind-backlog: while the drive is behind, waiting-list entries whose rank in their guess (1 = best) is above R wait (default: 0 = off). Needs --moe-stream-plan 1 |
| `--moe-stream-proj-ready 0\|1` | each RAM slot has a ready flag per projection (gate, up, down), and a needed read is issued as two requests, gate+up first, then down: the expert matmul starts an expert's gate and up as soon as they land, while its down is still being read. Same bytes, same text. Needs --moe-stream-overlap 1 (default: 0 = one flag per slot) |
| `--moe-stream-guess-inflight G` | with --moe-stream-plan 1, while no needed read is in service, a reader starts a guess piece or binds a list entry only while fewer than G guess pieces are in service (default: 0 = no limit). Needs --moe-stream-plan 1 |
| `--moe-stream-promote BOOL` | a needed expert whose guess read has chunks still queued moves them to the needed-read queue (default: false) |
| `--moe-stream-guess-cap N` | while a needed read is queued or running, at most N guess chunks are read at the same time (default: -1 = no cap) |
| `--moe-stream-guess-cap-refill BOOL` | with --moe-stream-guess-cap: a finished guess chunk wakes a sleeping I/O thread for the freed place while needed reads are in flight (default: false; untested) |

## What stays in RAM

| Flag | What it does |
|---|---|
| `--moe-stream-policy NAME` | how a layer's pool evicts: 'lru' (default), 'lfu' (the expert used most often, with every frequency halved every 64 accesses so the score tracks recent use) or 'slru' (a hit promotes a slot out of the probation segment, and victims come from probation first) or 'decay' (the lowest decayed use count, see --moe-stream-evict-halflife; a landed guess nobody used is worth 0, a guess for a layer that has not run yet in this word is kept; decode only, prompts keep lru) |
| `--moe-stream-protect-named 0\|1` | with --moe-stream-plan 1, while a streamed layer has not started in this decode word, a READY expert that a guess made this word for it named (any distance, any rank) is not a guess read's victim (a bind, at the list or at the pick); a needed read ignores the rule (default: 0 = off) |
| `--moe-stream-evict-halflife W` | with --moe-stream-policy decay: decode words after which a use counts half (default: 64) |
| `--moe-stream-evict-credit C` | with --moe-stream-policy decay: value added to an expert the 1-ahead guess ranked in its top 16 but the layer did not choose (default: 0) |
| `--moe-stream-prompt-end first-use\|recency` | wave order of a prompt's last ubatch: first-use (default) or recency (the experts the end of the prompt used most go last, so they stay in RAM for the reply) |
| `--moe-stream-prompt-end-halflife T` | with --moe-stream-prompt-end recency: tokens before the end of the prompt after which a use counts half (default: 128) |
| `--moe-stream-prompt-values BOOL` | with --moe-stream-policy decay: a prompt's expert uses count as decode words would (each use weighs 2^(-tokens to the end / --moe-stream-evict-halflife)), so the reply starts with values from the end of the prompt (default: false) |
| `--moe-stream-idle-load 0\|1\|2` | 1 = idle-time loading: after the model is loaded, and after every request once no call has come for --moe-stream-idle-pause, EMPTY RAM slots are filled with the most-used experts of the usage table (--moe-stream-usage-file), at the lowest read priority; it never evicts an expert, and a request stops it at once. The table is counted live (picks per expert per layer) and saved next to the sidecar by an atomic replace; the first start reads <table>-seed (counted from recordings) when the table does not exist yet. 2 = 1, and the model counts as loaded only once every RAM slot is filled: every expert when all fit, else each layer's most-used (the table, else its seed, else the seed in the model file; with no table in expert-id order), never an expert held in the VRAM pool; no time limit. The fill runs when the context is built, after the VRAM pool and before any request (so llama-server's health check follows it), with two reads per I/O thread queued; the first fill read of each streamed layer carries the read-back check (--moe-stream-verify), so its "read-back check done" line comes before the load ends. Progress on stderr: `llama_moe_stream: loading: experts into RAM P % (N of M, X of Y GB, S s)` at 0 %, every 10 % and 100 %, then one `llama_moe_stream: loading: experts into RAM done: ...` line. The first request does not start cold; the load takes longer. With --moe-stream-elastic 1 the fill, idle loading and --moe-stream-read-ahead fill only the slots switched on now (the pools sized at start from free RAM minus the RAM headroom; never a switched-off slot, a read never lands in a slot given back); during the fill and 10 s after it (until the first request) elastic RAM gives back only for a swap-out or free RAM under the headroom (no early give-back or file-cache trim from its rate estimates); a give-back during the fill switches off empty slots first and the fill skips them (the model always loads; idle loading fills what is left later) (default: 0) |
| `--moe-stream-usage-file FNAME` | the usage table of --moe-stream-idle-load ("tokenwing usage v1"; default: next to the sidecar, <sidecar>.usage.json; its seed is the same name with -seed before .json; with --moe-stream model the default is <model>.gguf.usage.json next to the model file, and with no seed file the usage seed appended to the model file is the seed). Keep it on the internal drive the model streams from |
| `--moe-stream-idle-pause MS` | with --moe-stream-idle-load 1 or 2, no call for this many milliseconds = idle (default: 500) |
| `--moe-stream-probation BOOL` | make a prefetched slot that nobody used the first eviction victim (default: false, i.e. uncovered prefetches are protected from eviction) |

## VRAM

| Flag | What it does |
|---|---|
| `-dev, --device <dev1,dev2,..>` | comma-separated list of devices to use for offloading (none = don't offload) use --list-devices to see a list of available devices (env: LLAMA_ARG_DEVICE) |
| `-cmoe, --cpu-moe` | keep all Mixture of Experts (MoE) weights in the CPU (env: LLAMA_ARG_CPU_MOE) |
| `-ncmoe, --n-cpu-moe N` | keep the Mixture of Experts (MoE) weights of the first N layers in the CPU (env: LLAMA_ARG_N_CPU_MOE) |
| `-ngl, --gpu-layers, --n-gpu-layers N` | max. number of layers to store in VRAM, either an exact number, 'auto', or 'all' (default: auto) (env: LLAMA_ARG_N_GPU_LAYERS) |
| `-sm, --split-mode {none,layer,row,tensor}` | how to split the model across multiple GPUs, one of: - none: use one GPU only - layer (default): split layers and KV across GPUs (pipelined) - row: split weight across GPUs by rows (parallelized) - tensor: split weights and KV across GPUs (parallelized, EXPERIMENTAL) (env: LLAMA_ARG_SPLIT_MODE) |
| `-ts, --tensor-split N0,N1,N2,...` | fraction of the model to offload to each GPU, comma-separated list of proportions, e.g. 3,1 (env: LLAMA_ARG_TENSOR_SPLIT) |
| `-fit, --fit [on\|off]` | whether to adjust unset arguments to fit in device memory ('on' or 'off', default: 'on') (env: LLAMA_ARG_FIT) |
| `-fitt, --fit-target MiB0,MiB1,MiB2,...` | target margin per device for --fit, comma-separated list of values, single value is broadcast across all devices, default: 1024 (env: LLAMA_ARG_FIT_TARGET) |
| `-fitc, --fit-ctx N` | minimum ctx size that can be set by --fit option, default: 4096 (env: LLAMA_ARG_FIT_CTX) |
| `--moe-stream-gpu-layers N` | keep the routed experts of N whole MoE layers on the GPU instead of streaming them: they are loaded from the model file and that layer's MoE runs entirely on the GPU, at the cost of one layer's worth of experts (1.494 GiB per layer on Ling-3.0-flash). A negative value fits as many layers as the free VRAM takes (default: -1, which is 4 layers on a 12 GB card at -c 4096; 0 streams every layer). A positive N is checked against the free VRAM before the load: the layers that do not fit next to the other weights, the context and the VRAM pool's minimum are streamed instead (the last picked first), with one line |
| `--moe-stream-gpu-layers-list LIST` | comma-separated MoE layer indices to keep on the GPU instead of streaming them, e.g. "5,17,38" (takes precedence over --moe-stream-gpu-layers). Checked against the free VRAM before the load: the layers that do not fit next to the other weights, the context and the VRAM pool's minimum are streamed instead, the list's last first, with one line; a context that still cannot be created in VRAM loads the model again with one layer fewer |
| `--moe-stream-gpu-layers-device DEV=LIST` | whole MoE layers whose routed experts sit on GPU DEV (a name as --list-devices prints it), whatever device holds the rest of the layer (its attention, KV cache, router and shared expert follow -ngl / -ts / --device as always): e.g. CUDA1=25-48 or CUDA0=2,3. Repeat it for more devices (or join them with ';'). The whole layers are every layer named, in the order given; when it is given, --moe-stream-gpu-layers-list and --moe-stream-gpu-layers are not used. Checked against each device's free VRAM before the load: the layers that do not fit are streamed instead, the last named on the device that is short first, with one line; a DEV that is not a GPU of the model streams its layers, with one line. LIST 'auto' (e.g. CUDA1=auto;CUDA2=auto): the first DEV named auto gets as many of the last streamed layers as fit in its free VRAM (keeping its --moe-stream-vram-free value free), the next the layers before those; the engine then places the layers itself: each whole layer runs completely on its DEV, every other GPU layer on the VRAM pool's GPU (--moe-stream-vram-device), and -ts does not decide (default: unset = whole layers sit on their layer's own device) |
| `--moe-stream-vram-device DEV` | the GPU (a name as --list-devices prints it, e.g. CUDA1) that holds the VRAM expert pool (--moe-stream-vram-free / --moe-stream-vram-experts) and everything that belongs to it, sized from that GPU's free VRAM; the prompt matmuls that read the RAM pools then run on that GPU only, so it is the one GPU that works with RAM and the SSD. It may differ from the GPUs that hold the streamed layers' attention and routers. A DEV that is not a GPU of the model keeps the first GPU, with one line (default: unset = the first GPU of the model's device list) |
| `--moe-stream-vram-reserve SIZE` | VRAM to keep free for the KV cache, the compute buffers and the driver when --moe-stream-gpu-layers is negative, so the auto-fit leaves room for them (default: 3.15GiB - the 2GiB measured at 4k ctx plus 1.15GiB that the fit used to over-count, so the placement stays the measured one; raise it for a large -c or -ub) |
| `--moe-stream-gpu-layers-mode MODE` | which layers --moe-stream-gpu-layers (negative) keeps on the GPU: 'hot' takes the ones a census measured as reading the most, 'last' takes the deepest ones. 'hot' is the default: it is worth 9 % more decode than 'last', and its KLD against no whole layer at all is 0.073, inside the 0.1528 that stock itself pays for putting the routed experts on the host instead of the GPU (tiny, measured) - both orders are rounding of the same weights, not a change of the model. 'hot' uses Ling-3.0-flash's layer ranking (43 blocks); for another model it falls back to shallowest-first and says so on stderr. With --moe-stream model the order is the file <model>.gguf.layer-order.json next to the model file, else the layer order appended to the model file |
| `--moe-stream-vram-experts N` | keep the first N experts of every streamed MoE layer's ranked list (--moe-stream-vram-experts-file) in VRAM: the GPU computes their pairs, the CPU the rest, and the SSD code never reads them. | `--moe-stream-vram-end-fill N` | with --moe-stream-vram-free's pool tail (a GPU-wave prompt empties it): 1 = refill the tail's free places at the end of the call that ends a prompt, best first by that call's prompt-end weights (its last tokens' experts; only experts READY in RAM, never an SSD read), instead of at the first reply word by VRAM follow's counts; 2 = also one VRAM follow tick over the per-layer VRAM places with the same weights. Default 0 = off |
| `--moe-stream-copy-ahead 0\|1\|2\|3` | with --moe-stream-vram-free's pool tail, GPU prompts copy the next wave's / layer's experts into the tail while this wave computes, and a prompt whose experts all fit one wave (every expert in RAM) takes the engine's own copy (tail waves) instead of the scheduler's whole-pool copy. Two sets of copy places: each step (the next wave or the next layer) copies into the other set while this one computes; one set: the next step's experts go into the places this wave's gate / up matmuls have finished with (a GPU mark tells the copier; needs needed-early's GPU form). 1 = two sets when one set costs at most a quarter of the GPU pool's room, else one; 2 = one set; 3 = two sets. | `--moe-stream-vram-lend-prompt 0\|1` | with --moe-stream-vram-free's GPU expert pool and --moe-stream-vram-follow, a prompt call's GPU compute buffer (ggml's own plan) lives in lent places of the pool; the real compute buffer holds the reply graphs and short prompt calls (see --moe-stream-vram-lend-short), so the pool holds more experts (refilled after the prompt). A tensor bigger than every lendable piece stays in the real buffer. Off by itself with a pinned --moe-stream-vram-experts N. Default 0 = off |
| `--moe-stream-vram-lend-short N` | with --moe-stream-vram-lend-prompt 1: prompt calls of at most N tokens (a short follow-up message) run in the real compute buffer, which is sized at start for such a call at the full context (measured); longer calls lend their plan from the VRAM pool. Default 64 |
| `--moe-stream-timing 0\|1` | 1 = measure where the time of every call goes - the host backend's compute, the device's kernels (CUDA events), the copies between backends and the waits for them - and report it per reply word next to the SSD wait, in llama-server's `GET /moe-stream/stats` and in `timings.moe_stream` of a response. ## Usage statistics

`llama-server` sends one anonymous record a day, after the model has loaded, so we can count how many people use the engine and how many start it directly or through an app. The record holds a random install id (made on first use and kept in the state folder), the date (UTC), the engine version, the OS name and version, the CPU name, the GPU names, and who started the engine (`direct`, or the value of `TOKENWING_LAUNCHER`). Never a prompt, a reply, a model name, a path or a user name. It is sent from its own thread with short timeouts: a failure (no network, a refusal) changes nothing and is not retried until the next start. The install id and the date of the last record live in the state folder: `$XDG_STATE_HOME/tokenwing` or `~/.local/state/tokenwing` on Linux, `%LOCALAPPDATA%\TokenWing` on Windows, `~/Library/Application Support/TokenWing` on macOS.

| Flag | What it does |
|---|---|
| `--no-stats` | do not send the daily anonymous usage record. The environment variables `TOKENWING_NO_STATS=1` and `DO_NOT_TRACK=1` turn it off too (default: sent) |

| `MOE_STREAM_TEST_WS_INELIGIBLE` | Names a word-start source layer V that counts as not eligible, so all sources keep the word-start op, and the run aborts if it needs --moe-stream-needed-early 1, --moe-stream-wordstart above 0 and the GPU producer and they are not there. |
| `MOE_STREAM_TEST_ZERO_WRITE` | When 1, each pool is allocated normally and its all-zero block is written at start and counted in the RAM plan, instead of being left unwritten. |
| `MOE_STREAM_VRAM_TEST_EMPTY` | When 1, the VRAM expert pool and its device pass exist but hold no expert, so every device id names a zero slice and the output must equal the run without --moe-stream-vram-experts. |
| `TOKENWING_STATS_URL` | Sends the usage record to this address instead of the real database (plain http allowed), so tests never write to it. |
